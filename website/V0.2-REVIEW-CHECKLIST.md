This document describes the current website analysis implementation and provides a practical review checklist. It is not a claim that v0.2 has passed independent testing.

## Current implementation

- Stockfish 19 lite single-threaded WebAssembly is hosted locally under `website/engine/stockfish-19.0.1/`.
- Quick Analysis uses 200 ms per position.
- Deep Analysis uses 1,200 ms per position and runs separately from Quick Analysis.
- Both modes analyse every position in the loaded game and show White/Black accuracy estimates, a game evaluation graph, move classifications, short explanations, and the engine's principal-variation suggestion.
- Completed analysis is cached locally by PGN and analysis mode. The user can explicitly reanalyse; Quick and Deep results are cached separately.
- The service worker cache version is updated when the analysis UI changes.
- The live board pulses the checked king's square, flashes the capture destination, and briefly fades/shrinks the captured piece glyph. Reduced-motion settings disable these effects.

## Important interpretation limits

- Accuracy is an estimate produced by Chess Master's current centipawn-loss heuristic. It is not an official Chess.com or Lichess accuracy score.
- Quick and Deep use different search times, so their results and estimates can differ. A forced reanalysis can also differ slightly between runs.
- Current move labels are Brilliant, Great, Good, Inaccuracy, Mistake, and Blunder. Brilliant is a conservative heuristic: it requires the opponent's principal-variation reply to capture material, a net material sacrifice of at least three points for the mover, and estimated centipawn loss no greater than 15 cp. It is not a full tactical proof; independent review should specifically measure false positives and false negatives.
- Move explanations are structured, contextual templates based on the move category and available move metadata. They are not generated natural-language engine reasoning and cannot prove why a move is strategically best.
- The displayed engine suggestion is the principal variation from the position before the played move, converted from UCI coordinates into SAN and limited to the first eight plies for readability. Verify conversion for castling, captures, promotions, checks, and checkmates.
- Mate scores, promotions, castling, en passant, terminal positions, and games with unusual PGN tags deserve specific testing.

## Latest v0.2 implementation updates

- Move explanations now use the move category plus available move context (capture, check, castling, promotion) and clarify that evaluation is engine/search-depth dependent. These are structured explanatory templates, not generated natural-language engine reasoning.
- Added an expandable variation explorer to each analysed move. It reconstructs the engine principal variation on a mini-board and lets the user step backward and forward through the line. It remains limited to the engine's displayed principal variation; it is not a multi-branch variation tree.
- Tightened the Brilliant heuristic: it now requires a near-best evaluation loss (15 cp or less), an actual opponent-PV capture of a valuable piece, and a material swing of at least three points. This remains a heuristic, not tactical proof, and must be checked for false positives/negatives.
- Added a visible Third-party notices page from the More navigation, with the bundled Stockfish GPL-3.0 notice/source references and chess.js 0.10.3 BSD-style license notice. This is attribution documentation, not a legal compliance certification.
- Bumped the analysis cache key to V4 because the cached move rows now contain variation and move-context data.

## Latest v0.2 polish

- Engine principal variations are now converted from UCI coordinate moves into readable SAN notation, with up to eight plies displayed per move.
- Move feedback now includes the estimated centipawn loss expressed in pawns, so reviewers can see the numerical basis behind each heuristic label.
- The local analysis cache key has been versioned to V3 so older cached rows with raw UCI variations are not reused.

## Current move-label thresholds

The current heuristic uses the estimated centipawn loss after a move:

- Brilliant: heuristic sacrifice condition above, with estimated loss no greater than 15 cp
- Great: 0–8 cp
- Good: 9–25 cp
- Inaccuracy: 26–60 cp
- Mistake: 61–120 cp
- Blunder: greater than 120 cp

These are implementation thresholds, not universal chess standards. An independent reviewer should validate or recommend recalibration.
