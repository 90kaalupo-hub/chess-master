# Chess Master v0.2 — Independent Review Notes

This document describes the current website analysis implementation and provides a practical review checklist. It is not a claim that v0.2 has passed independent testing.

## Current implementation

- Stockfish 19 lite single-threaded WebAssembly is hosted locally under `website/engine/stockfish-19.0.1/`.
- Quick Analysis uses 200 ms per position.
- Deep Analysis uses 1,200 ms per position and runs separately from Quick Analysis.
- Both modes analyse every position in the loaded game and show White/Black accuracy estimates, a game evaluation graph, move classifications, short explanations, and the engine's principal-variation suggestion.
- Completed analysis is cached locally by PGN and analysis mode. The user can explicitly reanalyse; Quick and Deep results are cached separately.
- The service worker cache version is updated when the analysis UI changes.

## Important interpretation limits

- Accuracy is an estimate produced by Chess Master's current centipawn-loss heuristic. It is not an official Chess.com or Lichess accuracy score.
- Quick and Deep use different search times, so their results and estimates can differ. A forced reanalysis can also differ slightly between runs.
- Current move labels are Great, Good, Inaccuracy, Mistake, and Blunder. A reliable Brilliant-move detector is not implemented yet; do not infer Brilliant status from the Great label.
- The short explanation text is a guidance hint based on the centipawn-loss category, not a natural-language engine explanation.
- The displayed engine suggestion is the principal variation from the position before the played move; review whether the PV is truncated or stale under unusual engine output.
- Mate scores, promotions, castling, en passant, terminal positions, and games with unusual PGN tags deserve specific testing.

## Suggested independent test checklist

1. Analyse the same PGN in Quick mode twice; confirm the saved result is reused until Reanalyse is selected.
2. Repeat in Deep mode and confirm it has its own independent saved result.
3. Force a reanalysis and verify the result panel, graph, progress bar, and button state recover correctly.
4. Test games with White winning, Black winning, a draw, and a decisive tactical swing.
5. Test checkmate, stalemate, repetition, insufficient material, castling, en passant, and pawn promotion.
6. Test short and long PGNs, including games with comments, headers, and unusual but valid metadata.
7. Compare move classifications against a trusted analysis at substantially higher engine depth; pay particular attention to borderline thresholds.
8. Verify the evaluation graph's sign convention: positive means White is better, negative means Black is better.
9. Verify both sides' accuracy calculations and ensure a side with no moves does not display a misleading score.
10. Test on a narrow Android screen, refresh after analysis, and confirm the service worker serves the latest version.
11. Test first-load engine startup, repeated engine use, a failed worker/WASM load, and offline reload after assets have been cached.
12. Review Stockfish and chess.js licensing, attribution, and the exact versions distributed with the website.

## Current move-label thresholds

The current heuristic uses the estimated centipawn loss after a move:

- Great: 0–8 cp
- Good: 9–25 cp
- Inaccuracy: 26–60 cp
- Mistake: 61–120 cp
- Blunder: greater than 120 cp

These are implementation thresholds, not universal chess standards. An independent reviewer should validate or recommend recalibration.
