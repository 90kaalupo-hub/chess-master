# Chess Master v0.4 — Offline AI Bots

## Status

Planning and implementation specification. This document does not mark any bot as implemented or tested. Website-first development remains the priority; Android work is paused. v0.3 is postponed and must not be pulled into this milestone.

## Product requirements

- Deliver 12 original, selectable AI opponents: Rookie, Scout, Rookie Plus, Tactician, Strategist, Guardian, Warrior, Wizard, Phantom, Grandmaster, Legend, and Chess Master.
- Cover beginner through master strength, with an intended range of roughly 400 to 2500+ Elo-equivalent. These are tuning targets, not guaranteed ratings; do not display a precise rating until calibrated against a suitable test set.
- All 12 opponents are free for Free and Premium users, unlimited, and ad-free.
- The player can choose to play as White or Black, or choose either side at game start.
- Core bot play must work offline after the website's assets and local engine have been cached.
- Use the existing self-hosted Stockfish 19.0.1 lite single-threaded WASM engine. Do not call a hosted chess API, scrape another chess site, or require sign-in/network access to make a move.
- Give each opponent an original short personality description and a distinct, understandable play style. Names and descriptions must be original to Chess Master.
- AI games are local practice games and must not change online ratings or be presented as rated games.

## Initial opponent ladder

The following bands are initial tuning targets for playtesting, not certified Elo ratings. Adjust them based on measured results.

| Opponent | Intended level | Personality direction |
|---|---:|---|
| Rookie | ~400–550 | Learning the rules; forgiving and simple |
| Scout | ~550–700 | Curious, develops pieces and spots basic captures |
| Rookie Plus | ~700–900 | More consistent basics; fewer free pieces |
| Tactician | ~900–1100 | Looks for forks, pins and direct tactics |
| Strategist | ~1100–1300 | Values development, king safety and plans |
| Guardian | ~1300–1500 | Solid, defensive and difficult to rush |
| Warrior | ~1500–1700 | Active, initiative-seeking and tactical |
| Wizard | ~1700–1900 | More calculation and positional awareness |
| Phantom | ~1900–2100 | Patient, resourceful and less predictable |
| Grandmaster | ~2100–2300 | Strong, accurate tournament-style play |
| Legend | ~2300–2500+ | Very strong, with few deliberate concessions |
| Chess Master | 2500+ target | Strongest available local-engine setting |

## Implementation architecture

1. Reuse the existing local Stockfish WASM asset; keep the engine self-hosted.
2. Give gameplay its own engine worker or a rigorously serialized command queue. The current analysis worker uses a pending-response callback and must not receive overlapping analysis and move-search commands.
3. Configure strength only through supported UCI options exposed by the bundled engine (for example, skill/strength options where available). Verify option availability from the engine's UCI response before relying on an option.
4. For lower levels, use controlled and reproducible strength reduction rather than random illegal moves or arbitrary material blunders. Keep all selected moves legal. Make randomness bounded and seedable during tests.
5. Set search limits appropriate to the opponent level and mobile browser performance. The strongest bot must remain responsive and must not freeze the board UI.
6. Keep bot configuration in one data-driven table so labels, descriptions, tuning and tests stay consistent.
7. Preserve the current local two-player mode, PGN import/review, saved-game history, sound controls and analysis features.

## Game flow and interaction

- Add a clear Play vs AI entry point and a compact opponent selection screen with all 12 opponents, level descriptions and a selected state.
- Let the player choose White or Black (and optionally random side).
- Show the chosen bot's name and status in the player strip; show a thinking indicator while the bot searches.
- Lock human input only while the bot is thinking or the game is over. Keep the page responsive and provide a recoverable error if the local engine cannot start.
- Trigger the bot after the human move when the position is still live. Handle checkmate, stalemate, repetition, insufficient material and other draw conditions through the existing chess rules library.
- In bot games, undo should remove the bot reply and the preceding human move as one turn when possible; do not leave the human waiting on the wrong side.
- Draw offers must be handled as a bot decision, and resign must award the result to the bot. These games remain local and unrated.
- Save bot name, side, and game mode with the local game record so history labels remain clear. Do not award local player-rating changes for bot games unless a separate, explicitly approved rating system is later designed.

## Acceptance tests

- All 12 bots can be selected and start a new game.
- Human can play as either color; bot always moves for the opposite color.
- Every bot move is legal and the game remains synchronized with the board and move list.
- Test opening, captures, check, checkmate, castling, en passant, promotion, stalemate, repetition and insufficient material.
- Bot thinking never overlaps analysis commands; analysis can still be run after a bot game without corrupting the engine state.
- Undo removes a complete human/bot turn; new game resets bot state.
- Draw offer, resignation, game saving, reopening and PGN export behave correctly.
- Engine loading failure, timeout, offline launch and low-memory/mobile-browser behaviour are handled without a frozen or unusable board.
- Confirm all assets needed for a previously cached game are available offline.
- Test strength ordering across a repeatable set of positions/games. Do not claim exact Elo values without calibration.
- Regression-test local two-player games and existing v0.2 analysis/review functionality.

## Out of scope

- v0.3 PGN/share-import validation and Chess.com link/synchronization work (postponed).
- Android implementation and phone testing (paused).
- Online multiplayer, accounts, cloud ratings, paid bot tiers, ads, or external engine services.
- Puzzles, lessons, social features and other later roadmap milestones.

## Delivery approach

Implement in small website-only changes on a feature branch, review the diff, run available static/syntax checks and targeted tests, and open a pull request. Do not merge or claim deployment without explicit user approval and verification.
